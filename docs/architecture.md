# Архитектура

## Общая схема

Form Service состоит из React-клиента и Express-сервера. Сервер хранит данные
в SQLite и отдаёт JSON API, а клиент использует TanStack Query для загрузки и
обновления серверного состояния.

```text
React pages/widgets/features
          │
          ▼
     apiAxios + TanStack Query
          │
          ▼
Express routes → controllers → services → repositories → SQLite
```

## Клиент

Клиент использует FSD-подобное разделение:

- страницы компонуют widgets и работают с route params;
- widgets собирают самостоятельные области интерфейса;
- features реализуют действия пользователя, включая mutations;
- entities содержат типы и API предметных сущностей;
- shared содержит общие UI-компоненты, API-клиент и конфигурацию.

После mutation актуальные данные из ответа сервера записываются в TanStack
Query cache. Лишние GET-запросы не выполняются.

## Сервер

HTTP-слой разделён на routes и controllers. Бизнес-правила находятся в
services, SQL — в repositories, а входные данные проверяются Zod-схемами до
передачи в бизнес-логику.

Операции, изменяющие несколько связанных записей, выполняются в SQLite
транзакциях. Формы состоят из страниц, страницы — из полей; позиции страниц и
полей нормализуются сервером.

## Важные ограничения

- административная панель работает без авторизации согласно требованиям MVP;
- опубликованные формы доступны по slug;
- форму с отправками нельзя удалить;
- последнюю страницу формы нельзя удалить;
- структуру формы с существующими ответами нельзя изменять так, чтобы нарушить
  целостность ответов.
